# Agent working friction, November 2026

This is the friction lanes hit in their working conditions: briefs, docs,
instructions, tools and the environment. Friction with Stitchwort itself
goes on the board as tickets instead. Each lane's report ends with a
"Working friction" section, and the orchestrator adds it here when the
lane is merged (D3673, Matt, 17 Nov 2026).

Once a week, a paper lane reads the entries, groups recurring patterns, and
proposes changes to `CLAUDE.md`, `docs/workflow.md`, the proving guide, the
lane agent definitions (`.claude/agents/`) or the brief templates. Matt
approves them.

Each entry gives:
- the date, ticket, model, and the task in one sentence;
- each item: what happened, roughly what it cost, and what would have helped.

## 17 Nov 2026 (seeded from the day's lane reports, before the section was required)

- `task test:one` for `hash_stability::prelude` rebuilt 44 test binaries
  and took about 4.5 min, over the two-minute rule. A `task` or a doc line

**SW-3461 (earlier, SW-3418 part 8), Sonnet.** Toy parser proofs.
- `task test:one -- rejected_examples_fail` scoped to 44 binaries, about
  3 min. This is the same problem as above.

**SW-3466 (earlier, SW-3418 part 9), Sonnet.** Toy parser proofs.
- The lane didn't know that the release binary reads std from the
  checkout, so std edits need no rebuild, and it rebuilt. This needs a line
  in `docs/workflow.md` or the proving guide.

**SW-3719, Opus.** Reshape the derived `==`/`<` proofs.
- The change moved about 257 example hash snapshots, but re-accepting them
  needs the whole `hash_stability::examples` run, which lanes may not run.
  The orchestrator had to finish it, and also missed
  `hash_stability::projects`, which Overmind's rolling check caught. A
  documented "hash-changing lane" path would help, saying who re-accepts
  which snapshot sets (prelude, examples, projects, AoC).
- A background wait loop the lane started kept running after its report.

**SW-3763, Opus review.** Review SW-3719's derived proofs.
- Derived declarations' names (`%sameSound`) can't be written in source,
  and `stitchwort doc` doesn't find them, so their types couldn't be
  printed to check that the statements were unchanged. It needed indirect
  evidence instead. A `dev` command that prints a declaration by its full
  internal name would help.

**SW-3743, Sonnet.** Toy++ T6.
- The worktree had no release binary, so the lane used the main checkout's
  for `stitchwort fmt` and `check`. It worked here, but it's wrong whenever
  the lane changed the compiler. The brief or `CLAUDE.md` should say which
  binary to use.

**SW-3743 and SW-3749, Sonnet.** Toy++ T6 and T7.

**SW-3772, Sonnet.** Formatter stage 0.

**SW-3728, DeepSeek.** Formatter fuzz case.
